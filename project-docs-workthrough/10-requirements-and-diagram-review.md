## 1. What the brief already gets right

These are kept as-is:

- File bytes are **not** stored in PostgreSQL. R2 holds the bytes.
- Large file data does **not** go through Supabase Realtime.
- Public IP is **not** to be treated as authorization (the brief asked for this to be challenged). **Updated 2026-09-23:** under the owner's rule for local mode (DEC-031), the network, which the server knows only through the public IP, *is* the access rule for local content. The design limits this to a Cloudflare-verified IP with fail-closed guards (DEC-032). Everywhere else (links, rooms, accounts) the IP still authorizes nothing.
- One-time download is **optional, not the default**, and must be race-free.
- Remote recipients must **not** browse the sender's local room.
- Team storage must have an **explicit quota**, and unlimited permanent storage is ruled out.
- Plan limits must be **enforced server-side**.
- The work is phased with human review gates.

## 3. Suggested wording updates for the diagram and marketing copy

The same-network wording stays as the owner wrote it (CR-001). Only the in-app audience copy is added, so users know who can see a local post.

| Current | Suggested |
|---|---|
| "Same network → Auto access" | Keep |
| "Users on the same network automatically see shared uploads" | Keep. In the app, before posting: *"Visible to everyone on this network · 3 devices here now."* |
| "No QR or link needed" | Keep |
| "Other networks cannot auto-browse local content" | Keep. Where local mode is off: *"Local sharing is off on this network. Use a link, QR code or share code instead."* |
| "Protected Access" | "Private link · optional password · expires automatically" |
| "Delete after first download" | "Delete after it's first downloaded" |
| "Files are automatically deleted after 7 days" | "Everything expires after 7 days on Free (up to 90 days on Pro)" |
| "Share Code e.g. ABCD-1234" | "Share code e.g. 7KQ4M-X9D2P (valid for 1 hour)" |
